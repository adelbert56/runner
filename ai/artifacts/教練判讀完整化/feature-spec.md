# 功能規格書：教練判讀完整化

## Metadata

- 功能：地形、天氣、恢復、賽事與補給的一致教練判讀
- 負責人：Squall
- 狀態：人工已授權；A 版已選定並實作
- 風險等級：中

## 問題

現行課表有總爬升、天氣與恢復的零散訊號，但無法用同一套證據避免錯誤加速、加量或把坡跑路況誤讀為能力變化。

## 目標

- 本機分析每段坡度、上下坡、心率、配速與步頻，且不保存 GPS 軌跡。
- 將睡眠、HRV、靜息心率、Body Battery、RPE、左腳／步態整合為可追溯放行門檻。
- 將溫度、濕度、降雨、坡度與跑步機條件標記為配速校正的資料品質條件。
- 賽事依角色保護課表，且提供賽後 48 小時回收資料與補給演練紀錄。

## 非目標

- 不上傳或公開 GPS 軌跡。
- 不用單一活動或單一賽果自動調整半馬目標。
- 不建立第二份平行課表。

## 使用者故事

| 故事 | 驗收標準 |
|---|---|
| 跑者想知道坡跑是否可比 | 坡度明顯的資料不會用來校正平路配速，且顯示上下坡摘要。 |
| 跑者想知道能否進度 | 所有恢復訊號列出可用／缺失／阻擋理由與決策。 |
| 跑者賽後想安全安排 | 48 小時資料未齊時，後續速度與長跑不進階。 |
| 跑者想重現補給策略 | 16K 以上長跑可記錄早餐、水分、電解質與腸胃反應。 |

## 資料與隱私

- 輸入：Garmin 詳細活動圖表、既有恢復資料、跑者回饋與長跑補給紀錄。
- 輸出：去識別化地形區段摘要（無座標）、條件標記、恢復決策與補給紀錄。
- 失敗：Garmin 詳細資料缺失時降級為總爬升判讀，不臆測逐段坡度。

## 驗收標準

- 每段統計不含經緯度或原始軌跡。
- 地形／天氣／恢復任一資料品質不合格時，禁止以該趟資料上調配速。
- UI 有預設、載入、空、錯誤、停用與窄螢幕規格。
