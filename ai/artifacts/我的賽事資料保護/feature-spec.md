# 功能規格書：我的賽事資料保護

## Metadata

- 負責人：Squall／Codex；狀態：使用者選定方案 A 並要求實作；風險：高（還原會取代本機資料）。

## 問題與使用者

賽事收藏、已報名清單與內容收藏保存在瀏覽器的裝置識別 localStorage；清除資料、換瀏覽器或裝置時可能無法找回。使用者是管理自己收藏與報名狀態的跑者。

## 目標與非目標

- 讓使用者能匯出與預覽還原上述三類資料，並在寫入前保留可驗證的現況快照。
- 還原預覽顯示備份與目前的數量，提供取消；檔案格式不符、快照失敗或預覽後資料變動均停止寫入。
- 不自動上傳、不合併不同版本、不變更訓練課表、Garmin、報名管理個資與付款資料；不使用其他裝置 ID 當成目前裝置。

## 使用者故事與驗收

| 故事 | 驗收 |
|---|---|
| 匯出 | 檔案包含格式版本、時間與三類資料；使用者可保存至其他位置，匯出失敗明示。 |
| 預覽還原 | 驗證格式及類型；呈現每類前後筆數，無效檔不得寫入。 |
| 保護資料 | 還原前保存並回讀目前快照；不成功則保留現況；預覽與確認之間有變更則取消。 |
| 例外處理 | localStorage 不可用、空資料、損壞 JSON、容量不足或取消皆有清楚結果；不隱藏失敗。 |

## 旅程與功能需求

從「我的賽事」或資料管理入口匯出；還原時選檔、核對數量，再明確確認。成功或失敗後保留可理解的狀態。備份是檔案，不代表雲端同步；檔案可包含賽事參與狀態，需提醒妥善保管。

## 畫面與資料/API

畫面狀態：預設、空資料、選檔、預覽、儲存失敗、還原成功、窄螢幕。資料來源：`site/app.js` 的 `FAVORITES_KEY`、`REGISTERED_RACES_KEY`、`CONTENT_FAVORITES_KEY`；僅本機檔案與 localStorage，不新增網路 API。格式與還原順序須於任務卡明定，並保留原始 key 相容性。

## 安全與驗證

避免在公開資源或日誌放入個人資料；限制檔案大小與資料型別，處理部分寫入失敗。測試匯出／匯入往返、損壞檔、儲存失敗、跨分頁變更與原值回復；UI 按專案規定選定 mockup 後另行驗證。此規格尚未實作或核准。
