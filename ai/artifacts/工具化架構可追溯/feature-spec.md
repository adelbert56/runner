# 功能規格書

## Metadata

- 功能：Runner 架構可追溯與按需知識導入
- 負責人：Codex
- 狀態：人工已核准、已實作
- 風險等級：中

## 問題

Garmin 同步、完成判定、正式教練處方與歷史資料保護分散在多個模組；既有專案地圖仍是範本，閱讀程式碼時難以快速驗證責任邊界。

## 目標

- 以可驗證、可版控的圖檔固定 Runner 的同步架構與完成判定資料流。
- 安裝三項工具：Archify、book-to-skill、diagram-design；不對現有產品 UI 與 Garmin 資料進行寫入。
- book-to-skill 僅允許轉換已授權、去識別化且可留存於本機的文件；本次只轉換專案內不含個資的 Garmin API 申請草稿。

## 非目標

- 不執行 Garmin 同步、不發布週報、不變更教練規則。
- 不將含個資、授權權杖或未授權文件送入 skill。
- 本階段不修改產品視覺介面；diagram-design 只新增專案內的說明文件。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 架構查核 | 身為維護者，我想查看實際同步責任與資料邊界，以便不混淆本機同步與教練決策 | 架構圖可由 JSON 重建並通過 9 項 showcase 檢查 |
| 完成判定 | 身為維護者，我想追蹤品質課完成判定如何流至週檢測，以便避免總距離誤認列 | 資料流圖可由 JSON 重建並通過 9 項 showcase 檢查 |
| 文件知識 | 身為維護者，我想按需查閱已授權 SOP，以便避免整份文件進入工作上下文 | `runner-garmin-training-api` 本機 skill 通過安全掃描；不含個資或 token |

## 安全性與隱私

- 不接觸 Garmin token、活動原始資料或加密週報內容。
- 供應鏈只採官方 GitHub 上游，安裝後記錄 `SKILL.md` SHA-256。
- book-to-skill 轉換前仍需逐份確認來源授權與個資清理。

## 驗收標準

- 三項工具安裝於使用者 Codex skills 目錄。
- 三張技術圖的 JSON 與 HTML 都存在，且 `validate`、`deliver` 成功。
- 文件明確說明技術圖不能取代實際同步／發布收據。
