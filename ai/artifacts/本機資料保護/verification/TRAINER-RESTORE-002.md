# TRAINER-RESTORE-002 驗證

- `node scripts/trainer-restore-safety-check.mjs`：合成資料驗證匯入前快照失敗、預覽期間版本改變、儲存失敗、匯入後還原；另執行實際 `saveData` 與雲端載入函式的失敗路徑。
- `npm run trainer:logic`：通過既有課表與生命週期邏輯檢查。
- `npm run ui:check`：通過靜態 UI 契約檢查。
- `node --check`：涉及的三個 Trainer 程式語法通過；`git diff --check` 通過。
- 限制：未以真實使用者資料或雲端帳號操作；未執行真實備份還原或真實瀏覽器互動。localStorage 檢查與寫入間不是跨分頁原子交易；一般編輯時其他呼叫端可能已先改變記憶體狀態，僅保證寫入失敗不通知同步或送出本機教練快照。快照與原資料仍在同一瀏覽器，不能替代獨立及異地備份。
- 資料比對：賽事正本目前 75 筆，網站本機副本 71 筆，名稱、報名狀態及其他欄位均有差異；未推斷哪份較新，未執行會覆寫兩檔的同步程式。
- 補充：`node scripts/trainer-backup-drill.mjs` 讀取最新獨立備份並驗證 SHA-256，以正式正規化、匯入及儲存邏輯在隔離的記憶體儲存空間中還原；22 週、255 筆紀錄、主要課程欄位及重建標記一致。未更動使用者瀏覽器或備份，亦未代表原始遺失紀錄已找回。
