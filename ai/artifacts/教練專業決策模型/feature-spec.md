# 功能規格書

## Metadata

- 功能：教練專業決策模型
- 負責人：Codex
- 狀態：草稿
- 風險等級：中

## 問題

現有教練課表過度把單一心率數字當成訓練指令，未清楚區分「目標區間」「安全上限」「當日取消條件」與「可選進階」。這會讓長跑在疲勞、天氣或補給不足時仍被誤讀為必須追心率或配速，且跑者回報的體感沒有成為同等權重的決策輸入。

## 使用者

- 主要：使用 Garmin 同步、以半馬為目標的跑者。
- 次要：檢視處方與實跑差異的教練／維護者。

## 目標

- 讓每堂課明確表達訓練意圖、可接受區間、上限／停止條件與降級方案。
- 讓長跑以可持續完成為第一優先；心率 155 只作目前個人長跑上限，不作追逐目標。
- 以心率、RPE、談話測試、症狀、天候、補給與前後恢復資料共同決定進階、維持或降級。
- 將品質課與長跑的壓力事件分開審核，避免因一次數據漂亮就自動增加速度與里程。
- 讓 Garmin、網站課表、加密週報與賽事指令使用同一個可稽核決策結果。

## 非目標

- 不做醫療診斷、傷病治療或取代醫療人員。
- 不以單次 Garmin 活動自動上調半馬目標或 VO2max 訓練負荷。
- 不承諾以固定比例、固定心率或固定週跑量適用所有季節與所有跑者。
- 不在未完成當週長跑與隔天恢復檢核前自動發布下一階段的間歇課。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 長跑指令 | 身為跑者，我想知道長跑的區間與何時改跑走，以便不把上限誤當目標。 | 長跑卡與 Garmin 同時顯示 130–155、155 是上限、疲勞或超限時的跑走方案；不可出現必做尾段高心率。 |
| 當日決策 | 身為跑者，我想在熱、累或睡不好時看到明確降級，而不是硬撐。 | 系統以 RPE、談話測試、天氣與恢復訊號給出維持／跑走／縮短三擇一，且不相互矛盾。 |
| 進階門檻 | 身為跑者，我想知道為何能或不能進下一階段，以便不用猜教練邏輯。 | 每次放行或阻擋都列出使用的 Garmin 結構、RPE、恢復與配速護欄證據。 |
| 壓力預算 | 身為跑者，我想避免同一週堆疊長跑、品質課與賽事，以便可恢復地進步。 | 系統每週列出壓力事件，超過預算時把第二個事件降為 E 跑並說明原因。 |
| 跨表一致性 | 身為跑者，我想手錶與網站看到同一堂課，以便執行時不用選一邊相信。 | 修改結構化課程後，發布前驗證 Garmin request、週報與畫面處方一致；替換回條必須記錄。 |

## 使用者旅程

```text
身為跑者
我在跑前看到「今天的意圖、區間、上限、降級方案」
跑中依談話測試、RPE 與心率執行，必要時直接改跑走
跑後同步 Garmin 與主觀 RPE
系統在隔天恢復資料到齊後，才對下週品質課作出可追溯決策
```

## 功能需求

- WHEN 課型為長跑且無安全保護狀態，THE SYSTEM SHALL 顯示個人長跑區間 130–155 bpm，並把 155 標為上限而非目標。
- WHEN 長跑中的 RPE 高於處方、談話測試失敗、心率持續超過上限、出現疼痛或步態改變，THE SYSTEM SHALL 指示跑走或縮短，且不得要求補量或收快。
- WHEN 長跑描述含「收快」或「漸進」，THE SYSTEM SHALL 將其標為「有餘裕才做」；不得提高長跑心率上限。
- WHEN 品質課、長跑品質段與賽事共用同一週，THE SYSTEM SHALL 計算壓力預算並限制為最多兩個事件。
- WHEN 準備放行間歇、增加長跑或上調配速，THE SYSTEM SHALL 要求結構化 Garmin 主課、RPE、隔天恢復和無症狀／步態改變四類證據；任一不足時不得自動進階。
- WHEN Garmin 課程結構改變，THE SYSTEM SHALL 比較 request 與已排程課程；同名舊課不得僅重用，必須以替換回條確認。
- WHEN 呈現訓練決策，THE SYSTEM SHALL 區分「觀測值」「護欄」「選項」與「必做項」。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 今日課程卡 | 預設、天候降級、疲勞降級、行動裝置版 | 顯示意圖、區間、上限與跑走方案。 |
| Garmin 同步預覽 | 結構變更、重用、替換失敗 | 顯示差異與實際替換回條。 |
| 週檢核 | 早期確認、正式確認、證據不足 | 列出放行／阻擋的四類證據與壓力預算。 |

## 資料與 API

- 輸入：Garmin 活動與結構分段、RPE、睡眠、HRV、靜息心率、天氣、主觀症狀、賽事日曆。
- 輸出：每堂課的意圖、可接受區間、上限、降級動作、壓力事件與下一階段判斷。
- 驗證：週報、Garmin request、教練目標與畫面輸出必須由同一決策物件衍生。
- 錯誤：缺少 RPE 或恢復資料時，標記「證據不足」，不把缺失推論為受傷或通過。

## 安全性與隱私

- 身分驗證：沿用現有本機 Garmin 配對與本機個人資料邊界。
- 權限：外部 Garmin 替換僅於明確課程修正後執行並保留回條。
- 敏感資料：健康、睡眠、HRV 與活動資料僅用於個人教練決策，不輸出原始活動流。
- 濫用情境：禁止用單一快段、單一心率或缺失的 RPE 自動升階；出現胸悶、暈眩等警訊時只提供停止與就醫建議，不做診斷。

## 驗收標準

- 長跑卡與 Garmin 均顯示 130–155 bpm，且清楚標註 155 是上限。
- 任一疲勞／症狀／超限條件觸發後，唯一建議是跑走、縮短或結束；不出現補量或追心率。
- 品質課與長跑的決策畫面可清楚區分課程意圖與心率護欄。
- 同一堂變更後的 Garmin 課程取得 `replaced` 或 `created` 回條；`reused` 不得視為結構更新成功。
- 至少有單元測試覆蓋長跑心率、RPE／談話測試降級、壓力預算、證據不足與 Garmin 替換偵測。

## 驗證計畫

- 單元測試：課程意圖解析、長跑區間、降級決策、壓力預算、進階閘門。
- 整合測試：週報、教練目標、Garmin request 同源一致性與加密週報建置。
- E2E：本機 Garmin 預覽與單日替換回條。
- 視覺：桌面與行動版課程卡，確認「上限」不會被視覺上呈現為必做目標。
- 手動：跑者確認談話測試、RPE 與實際感受是否與卡片文字一致。
