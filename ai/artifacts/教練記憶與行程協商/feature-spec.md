# 功能規格書

## Metadata

- 功能：教練記憶與行程協商
- 負責人：Codex
- 狀態：人工已核准（Squall 以「交給你」授權採用最少打擾方案）
- 風險等級：中

## 問題

現有 Trainer 能以 Garmin 與週檢核安全地調整課表，卻缺少可一眼追溯的「為何這樣安排」紀錄；跑者臨時不能跑時，仍需自行理解補跑與恢復的取捨。

## 使用者

- 使用 Garmin 同步、希望課表依真實生活調整的跑者。

## 目標

- 僅在有意義的事件發生時建立一筆可追溯的教練紀錄，不新增每日填表或跑後追問。
- 讓跑者可從未來課程直接宣告「這天不能跑」，由系統提出唯一安全替代方案或明確告知不補跑。
- 維持正式課表為唯一排程真相；歷史週永遠不因新建議回寫。

## 非目標

- 不新增自由聊天、LLM 自動改課或即時醫療診斷。
- 不要求跑者重複輸入 Garmin 已可提供的數據。
- 不更動 Garmin API、歷史課表快照或已完成課程。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 教練記憶 | 身為跑者，我想在教練頁看見近期改課的原因與下一個觀察點，以便理解教練沒有任意變動課表。 | 每筆含事件、處置、未採用方案、下一觀察點與日期。 |
| 行程協商 | 身為跑者，我想在未來跑課標記不能執行，以便直接取得安全的替代安排。 | 只能改未來且未完成的跑課；每次只給一個安全方案。 |
| 安全邊界 | 身為跑者，我想知道何時不應補跑，以便不把疲勞硬塞回週期。 | 無安全空檔時，明確保留休息、不新增補跑。 |

## 使用者旅程

```text
未來課程 → 點選「這天不能跑」→ 選原因 →
系統檢查強度間隔／休息日／已完成課程 →
顯示唯一安全安排或「本週不補跑」→ 確認 →
正式課表更新（僅未來）＋教練記憶新增一筆。
```

## 功能需求

- WHEN 正式課表因安全、Garmin、週檢核或行程協商改動，THE SYSTEM SHALL 建立 append-only 教練記憶。
- WHEN 跑者對未來跑課提出無法執行，THE SYSTEM SHALL 只評估未來休息日與既有補跑規則，且不得移動或覆寫歷史／已完成課程。
- WHEN 無安全替代日，THE SYSTEM SHALL 保留休息並說明不補跑的原因。
- WHEN 顯示教練記憶，THE SYSTEM SHALL 預設只顯示最近三筆，完整歷程採按需展開。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 教練建議／本週判讀 | 預設、空狀態、行動裝置版 | 顯示最近教練記憶，非重複的決策摘要。 |
| 未來課程抽屜 | 預設、無安全替代、已確認、行動裝置版 | 「這天不能跑」只在符合資格時可用。 |

## 資料與 API

- 輸入：既有 `appData.plan`、跳過原因、已完成紀錄、課程強度與日期。
- 輸出：`appData.coachMemory` append-only 事件；未來課程的既有補跑欄位。
- 驗證：事件需有唯一 ID、日期、來源、處置、下一觀察點；不接受歷史週寫入。
- 錯誤：資料不足或無可替代日，不寫入課表變更，只建立「未補跑」處置紀錄。

## 安全性與隱私

- 資料維持既有瀏覽器本地訓練資料邊界，不新增遠端傳輸。
- 疼痛、步態或極度疲勞仍交由既有 safety hold，行程協商不得解除保護。

## 驗收標準

- 不需每日新增輸入；手錶資料仍為主。
- 每次有效改動都可在教練頁追溯原因與後續觀察點。
- 行程協商只影響未來、未完成課程，且每次最多提供一個安全方案。
- 歷史週及既有正式課表快照不變。

## 驗證計畫

- 單元測試：擴充 `scripts/trainer-logic-check.mjs`。
- 整合測試：擴充 `scripts/ui-smoke-check.mjs`。
- E2E：擴充 `scripts/ui-layout-check.mjs`。
- 視覺：Playwright mobile、desktop 教練頁與未來課程抽屜。
- 手動：確認無安全替代日時不排補跑。
