# 功能規格書

## Metadata

- 功能：賽事列表至賽事詳情頁優化
- 負責人：Squall
- 狀態：草稿；資訊架構已由 Squall 確認，視覺變體待選定
- 風險等級：中（公開頁面導航、既有收藏／已報名／行事曆／排課操作必須完整保留）

## 問題

目前賽事清單同時承擔快速比較與完整決策資訊，單張卡片因而重複放入日期、地點、操作與資料事實。使用者提供的參考圖則是「一場賽事、一個清楚決策頁」：先看是否要跑，再看何時何地與如何行動，最後查看開跑、費用、名額與主協辦細節。

## 使用者

- 想快速比較多場中部賽事的跑者。
- 已鎖定一場賽事、需要確認報名、日期、地點、組別與排課行動的跑者。

## 目標

- 列表只保留日期、地區、距離、報名狀態與進入詳情的明確入口。
- 點選後提供參考圖風格的單一賽事詳情，讓主要行動與完整事實不互相搶焦點。
- 保留既有官方連結、加入行事曆、收藏、已報名與「用這場排課」行為及 localStorage 資料。

## 非目標

- 不新增帳號、雲端同步、付款或正式報名服務。
- 不推測或補造來源未提供的開跑、費用、名額或主協辦資料。
- 不更動賽事同步、去重、資料清理與 Trainer 課表演算法。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 清單比較 | 身為跑者，我想在列表快速比對日期、地區、距離、報名狀態，以便選出候選賽事。 | 每張清單列不重複承載詳情資料，四項摘要及「查看詳情」可辨識。 |
| 詳情決策 | 身為跑者，我想在單一賽事頁確認日期、地點、官方操作及事實資料，以便做出報名或排課決定。 | 主要動作、日期、地點、開跑／費用／名額／主協辦依資訊優先序顯示。 |
| 資料不完整 | 身為跑者，我想知道哪些資料尚待確認，以便不將未知內容誤認為官方資訊。 | 缺欄位隱藏或以既有「待確認」語意顯示，不能顯示虛構值。 |

## 功能需求

- WHEN 使用者點選賽事清單列，THE SYSTEM SHALL 以可分享、可返回的 URL 狀態開啟該賽事詳情。
- WHEN 詳情資料完整，THE SYSTEM SHALL 先顯示主行動、日期與地點，並在下方顯示可用事實卡。
- WHEN 賽事資料缺少某一事實欄位，THE SYSTEM SHALL 隱藏該卡；報名、日期等核心未知資訊沿用既有待確認語意。
- WHEN 使用者收藏、標記已報名、下載／加入行事曆或用此賽事排課，THE SYSTEM SHALL 保留現行行為與無障礙標籤。
- WHEN 使用者在手機檢視，THE SYSTEM SHALL 將詳情改為單欄、保持 44px 以上觸控目標與可返回列表的路徑。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 賽事列表 | 預設、載入、空、錯誤、行動版 | 快速比較與進入詳情。 |
| 賽事詳情 | 預設、載入、缺資料、錯誤、已過期／停辦、行動版 | 參考圖風格的單一賽事決策頁。 |

## 資料與 API

- 輸入：既有 `site/data/races.json`、URL 賽事 key、既有 localStorage 收藏與已報名狀態。
- 輸出：清單摘要與完整詳情畫面；沿用現有 Google Calendar／ICS、外部官方網址與排課入口。
- 驗證：只使用目前 `renderRaceCard` 已使用的欄位與既有 `escapeHtml` 安全編碼。
- 錯誤：資料讀取失敗沿用目前空／錯誤介面；找不到 URL 指向的賽事時回到可辨識的列表提示。

## 安全性與隱私

- 身分驗證：無。
- 權限：無。
- 敏感資料：收藏與已報名標記維持裝置本機 localStorage。
- 濫用情境：外連僅使用已存在且經 escapeHtml 處理的來源網址，維持 `target="_blank" rel="noreferrer"`。

## 驗收標準

- 清單／詳情的責任清楚分離，詳情資訊架構符合已確認的四段結構。
- 桌面與 390px 行動版不截斷標題、地點與主行動。
- 每個既有動作仍可用，且停辦／過期賽事不可排課。
- 所有資訊卡僅由實際資料欄位產生。
- 視覺沿用既有暖白、森林綠、黃色提醒 token 與既有 Button／Card／賽事事實列元件。

## 驗證計畫

- 單元／靜態：`node --check site/app.js`、既有 `npm run ui:check`。
- 整合：`npm run ui:layout`；以 URL 進入、返回列表、所有詳情動作的 DOM 檢查。
- 視覺：桌面與 390px 靜態預覽／截圖比對選定 mockup。
- 手動：確認本機收藏、已報名、行事曆與排課入口的端到端行為。
