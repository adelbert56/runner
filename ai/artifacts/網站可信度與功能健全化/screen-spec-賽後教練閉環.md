# 畫面規格

## Metadata

- 功能：網站可信度與功能健全化
- 畫面：Trainer 賽後教練閉環
- 狀態：草稿

## 目的

讓跑者一眼知道 10K 成績已被接收、目前缺少哪項證據、何時才會判讀，以及系統已採取的保守課表決策。

## 版面配置

- 主要區域：本週放行判讀與單一下一步。
- 次要區域：Garmin 成績、48 小時恢復、疼痛／步態、被拒絕的升級選項。
- 導覽：沿用 Trainer 的進度／分析頁籤。
- 動作：填寫 Garmin 無法提供的賽後恢復資訊、查看證據。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 顯示目前判定與證據列 | 不適用 | 截圖／logic test |
| 載入中 | 顯示等待 Garmin，同時維持原課表 | 正在等待 Garmin 活動 | DOM |
| 空狀態 | 尚未比賽時不要求回報 | 比賽後才需要填寫 | DOM |
| 錯誤 | 同步失敗時提供既有恢復路徑 | Garmin 尚未同步；目前不調整課表 | smoke test |
| 停用 | 未滿 48 小時或證據不足時禁用校正 | 證據不足，維持／降載 | logic test |
| 權限不足 | 未完成本機配對時不暴露私人資料 | 請從本機頁完成 Garmin 配對 | security smoke |
| 行動裝置版 | 判定、下一步、證據依序單欄 | 同上 | 390px 截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 填寫賽後恢復 | Garmin 活動已配對且缺恢復回報 | 只詢問疲勞、疼痛、步態與選填備註 | 欄位不完整不放行 |
| 查看判讀證據 | 任一狀態 | 展開 Garmin／恢復／規則證據 | 無資料時顯示缺口而非空白 |
| 評估後續課表 | 滿 48 小時且證據完整 | 交由既有 assessment／promotion gate | 任何安全風險均維持或降載 |

## 設計系統對照

- 用到的既有 design token：Trainer 的 `--c-surface`、`--c-surface2`、`--c-border`、`--c-primary`、`--c-primary-hover`、`--c-yellow`、`--c-text`、`--c-text-muted`、`--radius-md`、`--radius-lg`。
- 用到的既有元件：`coach-decision-card`、`coach-flow-card`、`coach-evidence-row`、Button、Modal、Form controls。
- 本畫面新做的元件：無；變體只重新組合已登記的教練判讀元件。

## 視覺驗收標準

- 主要判定與下一步在首屏可見。
- 清楚區分 Garmin 已知資料與跑者才需補充的恢復資訊。
- 缺證據、風險阻擋與可評估狀態不能只靠顏色辨識。
- 手機版不出現橫向捲動，按鈕可觸控且焦點可見。
- 不顯示第二份課表或暗示單場成績已自動升級。
