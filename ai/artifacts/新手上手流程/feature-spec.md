## 問題

`trainer.html` 目前的首次進站路徑是：空白狀態 → 直接進入 `renderSetupView()` 的訓練手冊設定表單（目標模式、日期、目標時間、訓練日、長跑上限…一次性全部要填）。表單本身有簡短說明文字（`site/trainer.js:1534`），但沒有任何內容說明：
- 這套系統整體在做什麼（自動排課＋依 Garmin 實績動態調整＋教練式判讀）
- 填完表單之後會得到什麼、要去哪裡看（本週課表／教練建議／週評估／進度與分析四個 tab 分別是什麼）
- 對不熟悉這類訓練管理工具的使用者，「訓練模式」「長跑日最長可跑時間」等專業詞彙的意涵

目標是讓「各式跑者都能夠參考此系統，練到他想要的目標」——這代表系統要對不同經驗程度、不同目標（新手 5K 到全馬）的使用者都好懂，不能只靠原作者本人已知的心智模型。

## 使用者

- 第一次使用這套系統、不熟悉「動態調整課表」概念的跑者。
- 有明確目標賽事但不確定該怎麼設定訓練模式/長跑時間上限的新手。
- （非首次但重新設定，如換目標賽事）沿用既有設定流程，不在本次範圍內重新設計。

## 目標

- 在使用者填寫設定表單「之前」，提供簡短、可跳過的說明，讓使用者理解這是什麼、大致怎麼運作。
- 對設定表單中專業或模糊的欄位（訓練模式、長跑日最長可跑時間等）提供跑者看得懂的說明或範例，而不只是欄位標籤。
- 已有課表的既有使用者（`hasExistingPlan` 為真）不應被迫重新看過完整上手流程。

## 非目標

- 不新增帳號系統、多人資料隔離或雲端同步（沿用現有純本機 localStorage 模型）。
- 不改變課表產生演算法（`buildPlan`/`buildPhases` 等，`trainer-plan.js`）或既有欄位的計算邏輯。
- 不做強制性、不可跳過的多步驟精靈（wizard）——尊重已熟悉系統或想快速設定完的使用者，上手內容須可一鍵略過。
- 不涵蓋「新手不知道自己目標配速/訓練日該怎麼選」這類訓練專業建議的自動推薦（可能是未來獨立功能，本次僅做說明與引導）。
- 不重新設計既有設定表單的欄位結構或視覺（如需要，屬於另一個 UI mockup 決策，不在本次 spec 範圍）。
- 不處理「產出課表後的下一步導覽」——已由重新接回的 `renderRunnerOnboardingCard()` 涵蓋，見上方「範圍變更紀錄」。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 認識系統 | 身為第一次使用的跑者，我想在填表單前用幾句話了解這套系統在做什麼，以便決定要不要花時間設定。 | 首次進站（`appData.profile` 不存在）顯示簡短系統說明，含「可跳過」或「開始設定」的明確出口，不強迫閱讀。 |
| 看懂欄位 | 身為不熟悉訓練術語的新手，我想知道「訓練模式」「長跑日最長可跑時間」等欄位在問什麼，以便填出符合自己狀況的設定。 | 表單中模糊欄位旁有跑者看得懂的補充說明或範例值，沿用既有 `field-help` 樣式。 |
| 老使用者不受打擾 | 身為已有課表的使用者，我不想每次進站或改設定都重新看一次上手流程。 | `hasExistingPlan` 為真時不顯示首次上手說明。 |

## 使用者旅程

```text
身為完全沒用過這套系統的新手跑者
我想在填表單前知道這是什麼、填完能得到什麼
以便有信心花時間把訓練日、目標時間等資訊填完整
```

## 功能需求

- WHEN 使用者首次進站且 `appData.profile` 不存在，THE SYSTEM SHALL 在設定表單上方顯示簡短系統說明區塊，含「開始設定」與可跳過的路徑。
- WHEN 使用者已有 `appData.profile`（`hasExistingPlan` 為真），THE SYSTEM SHALL 不顯示首次系統說明區塊，維持現有直接進入設定表單的行為。
- WHEN 使用者檢視「訓練模式」「長跑日最長可跑時間」等既有標記為需要補充說明的欄位，THE SYSTEM SHALL 顯示跑者可理解的補充文字或範例，沿用既有 `field-help`／`goal-desc` 樣式與位置。
- WHEN 使用者主動關閉或略過首次系統說明，THE SYSTEM SHALL 記住此狀態（本機儲存），不在同一裝置上重複顯示。

## 資料與 API

- 輸入：既有 `appData.profile`、`appData.plan` 存在性判斷（沿用 `hasExistingPlan` 邏輯）。
- 輸出：新增本機旗標（如 `appData.profile.onboardingSeen` 或等效欄位，命名由實作階段決定），標記使用者已看過首次系統說明，避免重複顯示。
- 驗證：新增欄位需符合 `normalizeData`（`site/trainer.js`）既有的資料正規化與預設值模式，不得讓缺欄位的舊資料觸發例外。
- 錯誤：本機儲存失敗（如 localStorage 不可用）時，上手說明可重複顯示，但不得阻擋設定表單填寫或課表產出等核心功能。

## 安全性與隱私

- 身分驗證：無。
- 權限：無新增。
- 敏感資料：新增旗標僅為布林值/時間戳記，不含個資。
- 濫用情境：不適用。

## 驗收標準

- 全新使用者（無 `appData.profile`）進站可看到系統說明，可一鍵跳過或關閉，不影響原本能直接填表單的路徑。
- 既有使用者進站與改設定的既有行為完全不變（不看到首次說明）。
- 表單中至少「訓練模式」與「長跑日最長可跑時間」有跑者看得懂的補充說明。
- 回歸驗證全綠：`npm run trainer:logic`、`npm run ui:smoke`、`npm run ui:layout`。

## 驗證計畫

- 單元／靜態：`node --check site/trainer.js`。
- 整合：`npm run ui:smoke`（新增：首次進站顯示說明／已有 profile 不顯示／關閉後不重複顯示的斷言）、`npm run trainer:logic`（確認 `normalizeData` 對新欄位的預設值不破壞既有資料）。
- 視覺：`npm run ui:layout` 桌面與行動裝置寬度；截圖比對首次說明區塊。
- 手動：清空本機資料模擬全新使用者，走過「看說明→填表單→產出課表」完整路徑；再以既有測試資料確認老使用者路徑不受影響。
