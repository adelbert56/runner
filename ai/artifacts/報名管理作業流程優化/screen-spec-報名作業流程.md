# 畫面規格

## Metadata

- 功能：報名管理作業流程優化
- 畫面：隊員首次建檔與賽事帶入後的報名建立
- 狀態：變體 A 已選定，實作完成

## 目的

讓操作者只需判斷當前一步，而非記住所有欄位、狀態與後續操作。

## 版面配置

- 主要區域：既有報名表單；上方加入簡短三步流程列。
- 次要區域：隊員表單的必填完成摘要；付款細節維持進階欄位。
- 導覽：沿用既有工作區 tabs、側欄賽事選擇與 URL hash。
- 動作：每個局部區域僅一個主動作：儲存人員或建立報名。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 新增人員時展開必填個資；報名表單顯示下一步 | 「完成基本資料後即可建立報名」 | 桌機截圖 |
| 載入中 | 沿用既有資料讀取狀態，表單不可送出 | 「正在讀取報名與賽事資料」 | DOM／截圖 |
| 空狀態 | 尚無隊員時指向新增人員 | 「先建立一位隊員，再帶入賽事」 | 桌機／手機截圖 |
| 錯誤 | 展開必填區、摘要缺欄、焦點到首欄 | 「請完成：手機、身分證號碼…」 | 表單互動測試 |
| 停用 | 尚無賽事或人員時，建立動作不可用 | 沿用既有按鈕 disabled | DOM 檢查 |
| 權限不足 | 非 loopback API 維持拒絕 | 沿用 API 錯誤 | API 測試 |
| 行動裝置版 | 步驟列維持三格、欄位單欄且觸控目標至少 44px | 不截斷主要按鈕與狀態 | 390px 截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 新增人員 | 點擊新增隊員 | 展開必填個資並聚焦姓名 | 未填時展開並指向首個未填欄 |
| 帶入賽事 | 側欄選定賽事 | 切至報名，標示步驟 1 | 尚無人員時顯示建立人員動作 |
| 選人與組別 | 有帶入賽事 | 流程列推進，保留多人選取 | 未選人或組別時不可把流程誤示為完成 |
| 建立報名 | 報名與付款狀態一致 | 寫入既有資料、回到待辦 | 付款未報名時阻擋並保留輸入 |

## 設計系統對照

- 用到的既有 design token：`--ink`、`--muted`、`--soft`、`--surface`、`--line`、`--green`、`--green-dark`、`--yellow`、`--radius`、`--radius-sm`、`--shadow-card`、既有 4/8/12/16/24/32px 間距 scale。
- 用到的既有元件：Button、Input、Select、Card、Nav、既有 status message、既有 workspace tab。
- 本畫面新做的元件：流程步驟列；依既有 Card／semantic color／radius 製作，需在實作完成後登記 inventory。

## 視覺驗收標準

- 第一次使用者在五秒內可讀出下一個必要動作。
- 三步流程只有當前步使用綠色；待處理以文字與編號表達，不只靠色彩。
- 完成摘要與錯誤文字在手機及桌面都完整可讀。
- 不新增孤立色彩、字級、間距、圓角或陰影。
