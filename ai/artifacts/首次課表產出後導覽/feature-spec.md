# 功能規格書

## Metadata

- 功能：首次產出課表後的四 tab 導覽
- 負責人：Squall
- 狀態：已實作；2026-08-23 由 Squall 核准（變體 A）
- 風險等級：低（純新增疊層/卡片，不改動任何課表資料或既有 tab 邏輯，可整段移除不影響其他功能）

## 問題

`新手上手流程`（`ai/artifacts/新手上手流程/feature-spec.md`）已於 2026-08-23 明確把這塊排除在範圍外，理由是「新手三步上手卡」（`renderRunnerOnboardingCard`，`site/trainer-render.js`）已重新接回、提供了「先做好這三步」的執行習慣引導。但重新檢視該卡片內容後，它談的是**執行節奏**（照卡片完成一堂／讀取 Garmin／週評估），完全沒提到**四個 tab 各自是什麼**：

- 本週課表 — 正式執行菜單
- 教練建議 — Garmin 判讀依據、風險提醒、逐週決策索引
- 週評估 — 每週回報、安全門檻
- 進度與分析 — 長期趨勢、週期管理

首次產出課表的新使用者，畫面預設停在「本週課表」，沒有任何線索告訴他「教練建議」「進度與分析」這些 tab 存在且將來會用到，容易整個週期都只看第一個 tab、錯過教練判讀與趨勢分析。

## 使用者

- 剛完成設定、第一次看到自己課表的新使用者。
- 已用過的既有使用者：不應被迫重新看過。

## 目標

- 首次產出課表後，讓使用者知道四個 tab 各自的用途，不必自己點開摸索。
- 引導只出現一次，且可主動關閉，不干擾之後的正常使用流程。
- 與已存在的「新手三步上手卡」內容互補、不重複（三步卡談執行節奏，這裡談 tab 是什麼）。

## 非目標

- 不重新設計四個 tab 本身的內容或版面。
- 不做不可跳過的強制精靈；使用者隨時可關閉，關閉後不重複出現。
- 不做互動式逐步高亮教學（如「點這裡」的 spotlight 導覽庫）——用靜態卡片說明即可，避免引入新的互動框架。
- 不影響既有使用者（已有 `appData.plan` 且已看過或無需看）的既有畫面。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 認識四個 tab | 身為剛產出第一份課表的新使用者，我想知道本週課表／教練建議／週評估／進度與分析四個 tab 各自的用途，以便知道之後要去哪裡看什麼。 | 首次產出課表後顯示一次性的四 tab 用途說明卡（可關閉），關閉後不再重複出現。 |
| 老使用者不受打擾 | 身為已看過或已有課表的使用者，我不想每次進站都重新看一次 tab 說明。 | 已看過（本機記錄）或無新課表可產出時，不顯示此卡片。 |
| 與三步卡不衝突 | 身為新使用者，我不想同時看到兩張內容重疊的引導卡片。 | 四 tab 說明卡與既有三步上手卡（`runner-guide-card`）視覺一致但內容互補，不逐字重複。 |

## 使用者旅程

```text
身為剛設定完成、第一次看到自己課表的新使用者
我想知道畫面上這四個分頁分別要幹嘛
以便之後知道遇到什麼狀況要去哪個分頁看
```

## 功能需求

- WHEN 使用者第一次成功產出課表（`appData.plan` 從無到有），THE SYSTEM SHALL 在本週課表 tab 顯示一次性的四 tab 用途說明卡。
- WHEN 使用者已看過此說明（本機已記錄）或非首次產出課表，THE SYSTEM SHALL 不顯示此卡片。
- WHEN 使用者主動關閉此卡片，THE SYSTEM SHALL 記住此狀態（本機儲存），不在同一裝置上重複顯示。
- WHEN 使用者看到此卡片，THE SYSTEM SHALL 讓四個 tab 名稱與其既有 tab 按鈕的文案一致（本週課表／教練建議／週評估／進度與分析），避免用詞不一致造成混淆。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 本週課表 tab — 四 tab 導覽卡 | 首次顯示、已關閉不再顯示、行動裝置版 | 插入位置在 `renderRunnerOnboardingCard()` 附近（`plan-tab-week` 區塊），與既有三步卡相鄰但不重疊。 |

## 資料與 API

- 輸入：`appData.plan` 存在性、既有 `appData.onboarding` 物件（已由 `renderRunnerOnboardingCard`/`dismissRunnerOnboarding` 使用，本次沿用同一物件加一個新欄位如 `appData.onboarding.tabIntroSeenAt`，不新建平行的儲存結構）。
- 輸出：本機旗標，標記已看過四 tab 導覽。
- 驗證：新增欄位需符合 `normalizeData`（`site/trainer.js`）既有預設值模式。
- 錯誤：本機儲存失敗時，卡片可能重複出現，但不得阻擋任何 tab 的正常瀏覽。

## 安全性與隱私

- 身分驗證：無。
- 權限：無新增。
- 敏感資料：無。
- 濫用情境：不適用。

## 驗收標準

- 首次產出課表後看到四 tab 說明卡，內容與既有三步卡不重複。
- 關閉後刷新頁面／重新進站不再出現。
- 既有使用者（已有課表、非首次）完全不受影響。
- 回歸驗證全綠：`npm run trainer:logic`、`npm run ui:smoke`、`npm run ui:layout`。

## 驗證計畫

- 單元／靜態：`node --check site/trainer-render.js`。
- 整合：`npm run ui:smoke`（新增：首次產出課表顯示導覽卡／關閉後不重複顯示／既有使用者不顯示的斷言）、`npm run trainer:logic`。
- 視覺：`npm run ui:layout` 桌面與行動裝置寬度。
- 手動：清空本機資料模擬全新使用者，走過「填表單→產出課表→看到兩張引導卡（三步卡＋四tab卡）→關閉四tab卡→確認不重複出現」路徑。
